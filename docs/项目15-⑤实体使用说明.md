## 2. 最重要的一条：实体上没有关联

**所有实体只有普通外键字段，没有任何 `@ManyToOne` / `@OneToMany`。**

```java
// Holding 里是这样
@Column(name = "portfolio_id", nullable = false)
private Long portfolioId;          // 不是 private Portfolio portfolio;
```

原因：`application.yml` 里 `spring.jpa.open-in-view: false`。
懒加载的关联一旦在事务外访问就抛 `LazyInitializationException`，
而这个异常出现的位置离真正的原因很远，排查成本高。

**需要跨表字段时用显式 JOIN 查询，别加关联。** 比如持仓列表要带公司名：

```java
public interface HoldingRepository extends JpaRepository<Holding, Long> {

    @Query("""
        select h, s.companyName
        from Holding h join Security s on s.symbol = h.symbol
        where h.portfolioId = :portfolioId
        order by h.symbol
        """)
    List<Object[]> findWithCompanyName(@Param("portfolioId") Long portfolioId);
}
```

返回 `Object[]` 不好看的话，定义一个 projection 接口或者 DTO 构造查询：

```java
@Query("""
    select new com.fnpis.portfolio.dto.HoldingRow(h.id, h.symbol, s.companyName, h.quantity, h.costBasis)
    from Holding h join Security s on s.symbol = h.symbol
    where h.portfolioId = :portfolioId
    """)
List<HoldingRow> findRows(@Param("portfolioId") Long portfolioId);
```

真的需要关联时找数据库负责人加，**不要自己往实体上补** ——
两个人对同一张表建两套映射，Hibernate 的一级缓存和脏检查都会出问题。

## 3. 复合主键的四个实体

`ArticleSecurityLink`、`PriceBar`、`PricePoint`、`PortfolioValuationSnapshot`
用 `@IdClass`，主键类是各自的静态内部类 `Key`。

Repository 的第二个泛型参数写这个 `Key`：

```java
public interface PricePointRepository extends JpaRepository<PricePoint, PricePoint.Key> {

    List<PricePoint> findBySymbolAndCapturedAtBetweenOrderByCapturedAt(
            String symbol, Instant from, Instant to);
}
```

按主键查：

```java
Optional<PricePoint> p = repo.findById(new PricePoint.Key("NVDA", instant));
```

`Key` 已经实现了 `equals`/`hashCode`，直接用。

## 4. 类型约定（写错会静默产生错数据）

### 金额、价格、数量一律 `BigDecimal`

**禁止 `double` / `float`。** Checkstyle 有一条正则会拦住
`double price` 这类命名，但拦不住所有情况，靠自觉。

比较大小用 `compareTo`，不要用 `equals`：

```java
// 错：scale 不同就不相等，2.0 != 2.00
if (holding.getQuantity().equals(BigDecimal.ZERO)) { ... }

// 对
if (holding.getQuantity().compareTo(BigDecimal.ZERO) == 0) { ... }
```

除法必须给 scale 和舍入模式，否则除不尽会抛 `ArithmeticException`：

```java
BigDecimal weight = holdingValue.divide(totalValue, 6, RoundingMode.HALF_UP);
```

scale 用 6 是对应 `DECIMAL(10,6)` 那批比例字段。金额用 4，对应 `DECIMAL(18,4)`。

### 时间戳一律 `Instant`，交易日一律 `LocalDate`

数据库存 UTC。**不要用 `LocalDateTime`**，它没有时区信息，
和数据库里的 UTC 值对不上会算错归因日（EC-16/EC-17）。

```java
Instant now = Instant.now();                    // 对
LocalDate today = LocalDate.now(ZoneOffset.UTC); // 对，显式给时区
LocalDate wrong = LocalDate.now();               // 错，用了本机时区
```

### 枚举字段直接赋枚举值

四个枚举字段都标了 `@Enumerated(EnumType.STRING)`，数据库存字符串。
你只管赋枚举，转换是 Hibernate 的事：

```java
score.setLabel(SentimentLabel.POSITIVE);
assessment.setAlignment(Alignment.CONFIRMED);
```

`SentimentLabel` 上有个现成的校验方法，D 模块用得上：

```java
if (!label.isConsistentWith(score)) {
    // POSITIVE 配负分是自相矛盾的输出，拒绝而不是存进去
}
```

## 5. 时间戳字段不用手填

`Portfolio`、`Holding`、`NewsArticle`、`SentimentScore`、`ImpactAssessment`、
`PortfolioValuationSnapshot` 都有 `@PrePersist` 兜底：字段为 null 时自动填 `Instant.now()`。

所以这样能work：

```java
Portfolio p = new Portfolio("US Account");
portfolioRepository.save(p);        // createdAt 自动填上
```

**但两个字段是例外，必须自己填，兜底不管：**

| 字段 | 为什么必须自己填 |
|---|---|
| `PriceQuote.asOf` | 数据源的采集时间。填 `now()` 会让过期数据看起来新鲜，砸掉 SC-009 |
| `PricePoint.capturedAt` | 同上，而且它是主键的一部分；`newsMarker` 竖线对齐到这条轴上 |

这两个是 `NOT NULL` 且没有 `@PrePersist`，忘了填会插入失败 —— 这是有意的，
比静默填个错时间好。

## 6. 派生字段：实体上没有，因为不该存

`Holding` 上**没有**市值、盈亏、权重字段。这三个都是读的时候现算：

```java
BigDecimal marketValue = holding.getQuantity().multiply(quote.getPrice());
BigDecimal pnl = marketValue.subtract(holding.totalCost());
```

`holding.totalCost()` 是实体上现成的方法（数量 × 成本价）。

同理 `PriceQuote` 上没有 `changePct`，只有 `change()` 方法算绝对涨跌额，
前收盘为 null 时返回 null：

```java
BigDecimal change = quote.change();          // null 表示算不出
```

不存派生值的理由：价格一刷新，存下来的市值立刻就是错的。

### 比例 vs 百分数

`ImpactAssessment` 里所有比例字段**存的是比例**：

| 字段 | 库里的值 | API 输出 |
|---|---|---|
| `priceChangeRatio` | `0.041500` | `"priceChangePct": 4.15` |
| `observedContribution` | `0.012580` | `"observedContribution": 1.258` |
| `holdingWeight` | `0.303000` | `"holdingWeight": 0.303`（本来就是比例，不乘） |

**×100 只在 API 出口做一次。** 两处都乘会得到 415%，这是这个项目最容易出的错。

## 7. 改了实体必须同时改迁移脚本

`spring.jpa.hibernate.ddl-auto: validate` 是开着的：

> **实体和表结构对不上，应用直接启动失败。Hibernate 不会帮你改表。**

报错长这样：

```
Schema-validation: wrong column type encountered in column [quantity] in table [holding]
```

这是有意的（Flyway 独占 schema 所有权），但意味着：

- 加字段 → 必须同时加 `V8__xxx.sql`，否则**全组启动失败**
- 改精度 → 同上。`precision`/`scale` 必须和 SQL 完全一致
- 只改注释、加方法 → 不影响映射，安全

所以实体改动走数据库负责人，一次改两边。

字段对齐的样子：

```java
@Column(name = "quantity", nullable = false, precision = 18, scale = 4)
private BigDecimal quantity;      // SQL: quantity DECIMAL(18,4) NOT NULL
```

## 8. 环境要求：本机 JDK 不要用 25

实体用了 Lombok 的 `@Getter` / `@Setter` / `@NoArgsConstructor`。

**Spring Boot 3.3.5 锁的 Lombok 1.18.34 不支持 JDK 25，而且是静默失败** ——
不报任何警告，就是不生成 getter/setter。你会看到 `holding.getSymbol()` 编译不过，
但报错看起来像实体写错了，完全不像工具链问题。

已验证可用：**JDK 21**（Temurin 21.0.11）。CI 用的是 **JDK 17**。
`maven.compiler.release=17` 保证本机 21 编出来的字节码是 Java 17，和 CI 一致。

自查一句：

```bash
javap -p target/classes/com/fnpis/domain/Holding.class | grep getSymbol
```

有输出就正常，没输出就是 Lombok 没生效，换 JDK。

## 9. 各模块的 Repository 起步

放各自模块的包下，不要都塞在一个 `repository/` 里。

```java
// 模块 A
public interface PortfolioRepository extends JpaRepository<Portfolio, Long> { }

public interface HoldingRepository extends JpaRepository<Holding, Long> {
    List<Holding> findByPortfolioId(Long portfolioId);
    Optional<Holding> findByPortfolioIdAndSymbol(Long portfolioId, String symbol);
}

// 模块 B
public interface PriceQuoteRepository extends JpaRepository<PriceQuote, String> { }
public interface PriceBarRepository extends JpaRepository<PriceBar, PriceBar.Key> { }
public interface PricePointRepository extends JpaRepository<PricePoint, PricePoint.Key> { }

// 模块 C
public interface NewsArticleRepository extends JpaRepository<NewsArticle, Long> {
    Optional<NewsArticle> findByExternalId(String externalId);
    boolean existsByExternalId(String externalId);
}

// 模块 D
public interface SentimentScoreRepository extends JpaRepository<SentimentScore, Long> {
    Optional<SentimentScore> findByArticleId(Long articleId);
}

// 模块 E
public interface ImpactAssessmentRepository extends JpaRepository<ImpactAssessment, Long> {
    List<ImpactAssessment> findByPortfolioIdAndAttributionDate(Long portfolioId, LocalDate date);
}
```

`Security` 和 `PriceQuote` 的主键是 `String`（symbol），不是 `Long`。

### 幂等写入

四张表靠唯一约束保证幂等，定时任务重跑不会产生重复。用「先查再写」而不是
硬插，或者用 `@Query` 写原生 upsert：

| 表 | 约束 | 重跑时 |
|---|---|---|
| `news_article` | UNIQUE(external_id) | 先 `existsByExternalId` 再插 |
| `sentiment_score` | UNIQUE(article_id) | 先 `findByArticleId`，有就跳过（省 LLM 调用） |
| `holding` | UNIQUE(portfolio_id, symbol) | 先 `findByPortfolioIdAndSymbol`，有就合并算加权成本（EC-09） |
| `impact_assessment` | UNIQUE 四列 | recompute 用 upsert |
| `price_point` / `price_bar` / 快照 | 复合主键 | `save()` 天然覆盖 |

直接硬插会撞 `DataIntegrityViolationException`，那不算 bug，
是约束在提示你逻辑写漏了。

## 10. 实体上没有 equals / hashCode

十一个实体都没有重写 `equals`/`hashCode`（`Key` 内部类有，那是主键要求）。

**不要往实体上加 Lombok 的 `@Data` 或 `@EqualsAndHashCode`。**
它们会把所有字段纳入比较，对 JPA 实体是错的：新建对象 id 为 null，
存库后 id 变了，hashCode 跟着变 —— 放进 `HashSet` 的对象会找不回来。

需要判断是否同一行就比 id：

```java
if (Objects.equals(a.getId(), b.getId())) { ... }
```
