VALIDATION FIRST
One LLM Agent, one JSON shape, one stored result
Three fields, nothing else. We do not trust the headline, and we do not trust the answer — nothing is saved unless it looks exactly like this.
{
  "label": "NEGATIVE",
  "score": -0.82,
  "confidence": 0.97
}
Model · claude-opus-4-8Temperature 0, so the same headline gives the same answer
Limit 01 · Small jobOne headline in, one JSON object out, and a 256-token cap
Limit 02 · Self-checkIf the score and the label disagree, we keep the score and fix the label
Limit 03 · Our code decidesThe model proposes an answer; our code decides whether to save it
DIRECTION ≠ ALIGNMENT

We separate prediction from market evidence

DIRECTIONNewsPOSITIVE / NEGATIVE / NEUTRAL — from the news alone
CONFIRMEDAgreePrice moved in the same direction as the headline
DIVERGENTSignalThe price went the other way — and that is worth knowing
INCONCLUSIVEWaitToo small to mean anything, or no price to compare
Both of these describe what happened · neither one says buy or sell · a system that can say "we don't know" is not giving advice
HOW IT FAILS

Failure was designed, not discovered

01
Breaks at startup, not on stage
If a key is missing or the database does not match the code, the app refuses to start — so we find out before the demo, not during it.
02
Any provider can be swapped
If a price source goes down we fall back to another one, and the rest of the system never notices the difference.
03
One answer per article
A verdict is written once and never rewritten. If the call fails we raise an error rather than guess NEUTRAL.
04
24 edge cases written down
Seventeen already have a test. Three of them are divide-by-zero traps we hit on purpose.
05
Double-click is harmless
A second refresh is turned away instead of queued. Running it twice would change nothing and only waste our API quota.
06
Tests run on real MySQL
Not an in-memory stand-in. Decimal precision and index limits only behave like production on the real database.
