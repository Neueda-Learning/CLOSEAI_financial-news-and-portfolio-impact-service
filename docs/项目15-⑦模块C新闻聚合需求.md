# 项目 15 模块 C 新闻聚合需求

## Financial News & Portfolio Impact Service

> 版本 v1.0 ｜ 2026-07-29
> 前置文档：`项目15-②架构设计.md` §4.1、§5、§6.5、§7.1｜`项目15-⑤实体使用说明.md`
> 对应需求：C1–C6｜边界条件 EC-01、EC-02、EC-14、EC-20、EC-24
> 负责人：模块 C

本文档讲一个定时任务：每 15 分钟从 Finnhub 拉取 watchlist 中每只股票的新闻，
去重后写入 `news_article` 和 `article_security_link` 表。
与模块 B 的报价刷新是同一种调度模式，但数据流不同 —— 见第 4 节。

---

## 1. 为什么这个任务不能等

`impact-view`（F4 联动视图）需要新闻数据来渲染左侧面板和那根竖线（`newsMarker`）。
没有新闻就没有情感分析，没有情感分析就没有影响评估 ——
Module C 是整个项目中「必须最先跑起来的数据管道」。

`news_article.external_id` 上的 UNIQUE 约束意味着这个任务是去重的安全网：
新闻只插入一次，不会因为调度器重复跑而堆积。同样，`sentiment_score.article_id`
是 UNIQUE 的，所以一篇新闻只会被 LLM 分析一次 —— 延迟启动就延迟了情感数据的生成。

**去重是只认 external_id 不认内容的。** 同一篇 Reuters 文章被两个 ticker
的 company-news 端点返回时，external_id 相同 → 文章复用，但
`article_security_link` 为每个 ticker 独立建一行（EC-24 多对多）。

## 4. 数据流与去重逻辑

### 4.1 从 Finnhub 到数据库

```
Finnhub /company-news?symbol=AAPL&from=...&to=...&token=***
  ↓ (JSON array of FinnhubNewsResponse)
FinnhubNewsProvider.fetchCompanyNews()
  ↓ (filter blank headlines & zero timestamps — EC-14)
  ↓ (map to NewsItem records — inside the provider, not in the service)
List<NewsItem> (record, 非 @Entity)
  ↓
NewsFetchService.fetchAll()
  → for each symbol → NewsPersistenceService.persist(symbol, item)
      ├── article = articleRepo.findByExternalId(externalId)
      │             .orElseGet(() → articleRepo.save(toEntity(item)))
      └── if (!linkRepo.existsById(key))
              linkRepo.save(new ArticleSecurityLink(...))
```

### 4.2 去重规则

**文章层面：** `news_article.external_id` 有 UNIQUE 约束。
同一条 Finnhub 文章（同 id）被多次拉取 → `findByExternalId` 命中 → 复用已有行，不重复插入。

**关联层面：** `article_security_link (article_id, symbol)` 是复合主键。
同一篇文章被两个 ticker 的 API 返回时（例如 "chip stocks rally" 同时出现在 AAPL 和 NVDA 的 company-news 里），article 行只存一条，但 link 表为每个 ticker 各存一行。

**所以一次 refresh 的语义是：**
- `fetched` = 成功调通的 symbol 数
- `inserted` = 新创建的 article_link 行数
- `skippedDuplicates` = link 已存在被跳过的数量
- `failures` = provider 或持久化异常数

## 5. 限流与降级

**限流器已配好：**

```yaml
resilience4j:
  ratelimiter:
    instances:
      finnhubNews:              # 新闻专用
        limit-for-period: 30
        limit-refresh-period: 60s
```

```java
@RateLimiter(name = "finnhubNews")
@Retry(name = "externalApi")
```

**绝对不要共用 `finnhubPrice` 实例**（架构 §6.5 要求 1）。
新闻和行情用不同账号、不同 key、不同限流器，一个链路的 429 只降级自己。

**429 不重试。** `retry.instances.externalApi` 已配置 `ignore-exceptions: HttpClientErrorException`。

**失败处理：单个 symbol 拉取失败时记日志跳过，继续处理下一个。**
读接口始终从库出——上游挂了出旧数据加 `stale: true`，不报错。

**日志里不许出现 key。** FinnhubNewsProvider 通过 Spring RestClient 的 URI 变量
（`{token}`）传递 API key，key 不会出现在日志的 URI 模板中。
但若开启 `logging.level.org.springframework.web.client=DEBUG`，
完整的请求 URI（含 token 值）会出现在调试日志中 ——
生产环境须避免开启此级别，或实现 `ClientRequestInterceptor` 做参数脱敏。

## 6. 调度策略

**定时触发：**

```java
@Scheduled(fixedDelayString = "${app.schedule.news-poll-delay}")  // 900000ms = 15min
```

15 分钟轮询一次。免费版 Finnhub `/company-news` 有 60 次/分钟的额度，
15 只标的 × 每只 1 次调用 = 15 次/轮，远在额度内。

**新闻没有交易时段限制**，7×24 跑。新闻在休市日也会发布（盘后财报、周末突发事件），停掉轮询会错过这些。

**用 `fixedDelay` 不是 `fixedRate`**，原理同 Module B §7：上一轮结束后才开始计时下一轮，任务永远不会和自己重叠。

## 7. 并发与执行锁

与 Module B 完全相同的模式：

```java
private final AtomicBoolean running = new AtomicBoolean(false);

public boolean tryAcquire() {
    return running.compareAndSet(false, true);
}
```

**拿不到锁返回 409，不排队。** 新闻轮询是去重的（`external_id` UNIQUE），跳过一次最多晚 15 分钟，排队会在上游恢复时打出堆积请求触发限流。

手动触发和定时任务用的是**同一个锁**（`NewsFetchService.running`），不是两个独立的锁 —— 所以 `manualFetch()` 和 `scheduledFetch()` 互斥。

## 8. 事务边界

```java
// NewsPersistenceService — 单篇文章 + link 在同一事务内
@Transactional
public int persist(String symbol, NewsItem item) { ... }

// NewsFetchService — 遍历时每个 symbol 独立
// 不做大事务包裹：一个 ticker 失败不回滚其他 ticker
```

**独立 bean 是故意的。** `@Transactional` 在 Spring AOP 下只能拦截从另一个 bean
调用的方法。如果 `persist` 写在 `NewsFetchService` 内部，`this.persist()` 不会走代理，事务不生效。拆成两个 bean 后 `fetchAll()` 里的 `persistence.persist()` 才会被拦截。

## 9. 字段截断与安全

Finnhub 返回的字段长度不受控制，`FinnhubNewsProvider` 截断到数据库列宽：

| 字段 | 列宽 | 截断规则 |
|---|---|---|
| headline | VARCHAR(512) | 超长截断 |
| source | VARCHAR(64) | 超长截断 |
| url | VARCHAR(1024) | 超长截断；null → `""` |
| summary | TEXT | 不截断（V8 migration 加的） |
| image | TEXT | 不截断，null → `""`（V9 migration，CDN URL 可能超长） |

**EC-14 过滤：** headline 为空或 `datetime` 为 0 的新闻直接丢弃，不存入库。

## 13. 与模块 B 的差异速查

| 维度 | 模块 B (行情) | 模块 C (新闻) |
|------|:--:|:--:|
| 定时频率 | 1 分钟（交易时段） | 15 分钟（全天） |
| Provider 接口 | `PriceProvider` (3 种实现 + 链) | `NewsProvider` (1 种实现) |
| 写库语义 | upsert（price_quote 覆盖，price_point 追加） | merge（externalId 唯一，重复跳过） |
| 执行锁 | `AtomicBoolean` | `AtomicBoolean`（同模式） |
| 限流器 | `finnhubPrice` | `finnhubNews` |
| 多对多 | 不涉及（一个 symbol 只影响自己） | `article_security_link` 承载多对多 |
| 降级 | Twelve Data fallback | DB 缓存 fallback（无备用新闻源） |
| 手动触发 | `POST /api/v1/quotes/refresh` | `POST /api/v1/news/refresh` |
